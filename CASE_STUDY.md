# Case Study: From a TF-IDF Baseline to a Deployed, Monitored Sentiment Analysis API

## Overview

This project was completed over six weeks as part of an Applied NLP Engineering internship at Sohail Smart Solutions. Rather than focusing only on building a sentiment classifier, the objective was to follow the complete machine learning lifecycle—from data preparation and model evaluation to deployment, monitoring, and documentation.

The final result is a publicly deployed sentiment analysis API built with FastAPI, Docker, and Hugging Face Spaces. The service accepts user text, predicts whether the sentiment is Positive, Negative, or Neutral, returns a confidence score, and exposes monitoring endpoints for operational metrics.

---

## The Problem

The goal of the project was to automatically classify text into three sentiment categories: Positive, Negative, and Neutral. While sentiment classification is a common Natural Language Processing (NLP) task, building a reliable solution requires much more than simply training a machine learning model.

The project needed to solve several challenges, including text preprocessing, feature engineering, model evaluation, error analysis, deployment, and production monitoring.

---

## Project Evolution

The project began with a traditional TF-IDF feature representation combined with a Logistic Regression classifier. This baseline provided a simple and interpretable starting point, but further evaluation showed that it struggled to understand sentence meaning and word relationships.

Instead of immediately replacing the model, additional experiments were performed to understand why these errors occurred. The dataset was expanded and improved, more detailed evaluation metrics were introduced, and confusion matrices were used to analyse model behaviour beyond overall accuracy.

The next stage explored averaged GloVe word embeddings. Unlike TF-IDF, GloVe captures semantic relationships between words, resulting in better classification performance. However, averaging word vectors removes sentence structure and context, meaning the model still struggled with negation and more complex language patterns.

The final feature representation used contextual sentence embeddings generated by the **all-MiniLM-L6-v2** transformer model. Because transformer embeddings consider the entire sentence instead of isolated words, they capture sentence meaning much more effectively. The contextual embeddings were combined with the same Logistic Regression classifier, allowing the feature representation itself to be evaluated fairly while keeping the classifier constant.

---

## Results

Using the same dataset, preprocessing pipeline, classifier, and five-fold cross-validation throughout the comparison produced a clear progression in performance.

| Feature Representation | Accuracy | F1 Score |
|------------------------|---------:|---------:|
| TF-IDF | 69.5% | 68.2% |
| Averaged GloVe | 74.3% | 73.8% |
| MiniLM Sentence Embeddings | **82.4%** | **82.1%** |

The MiniLM model improved the F1 score by **13.9 percentage points** compared with the original TF-IDF baseline, making it the final model selected for deployment. Earlier error analysis also showed that contextual embeddings reduced total cross-validation errors from **64 to 37**, reducing the overall error rate from **30.5% to 17.6%**.

---

## Error Analysis

Rather than relying only on accuracy, every model was analysed using precision, recall, F1-score, confusion matrices, and manual inspection of incorrect predictions.

This analysis showed that the baseline TF-IDF model frequently confused Positive and Negative sentiment, particularly for sentences containing negation, sarcasm, mixed opinions, and uncommon vocabulary. For example, expressions such as *"not the worst experience"* remained difficult because bag-of-words features cannot fully understand sentence structure.

The MiniLM sentence embedding model addressed many of these weaknesses by generating contextual sentence representations instead of relying only on word frequency or averaged word vectors. This significantly reduced misclassifications while improving overall robustness.

---

## Deployment and Monitoring

After selecting the final model, the project moved beyond experimentation and into production deployment.

The trained Logistic Regression classifier was saved using Joblib, while the pretrained MiniLM encoder was loaded directly through the Sentence Transformers library. A FastAPI application was developed to expose prediction endpoints, followed by input validation to prevent invalid requests.

The application was then containerized using Docker and deployed to Hugging Face Spaces, making the API publicly accessible. To improve production readiness, structured logging and monitoring were added. Every prediction records timestamps, request IDs, confidence scores, input length, and response latency, while a dedicated `/metrics` endpoint reports operational statistics such as request count, error count, average latency, prediction distribution, and low-confidence predictions.

During deployment testing, the API successfully processed **16 live prediction requests** with **zero errors**, while maintaining an average response latency of approximately **35.26 ms**.

---

## Limitations and Future Work

Although the final system performs well on English sentiment classification, several limitations remain. The model was trained primarily on English text, so unsupported languages such as Arabic may produce unreliable predictions. In addition, free cloud hosting introduces short cold-start delays after periods of inactivity.

Future improvements could include multilingual support, automatic language detection, larger training datasets, fine-tuning the transformer model directly on the sentiment dataset, and integrating external monitoring platforms for long-term production analytics.

---

## Conclusion

This project demonstrates the complete evolution of a machine learning application from an experimental NLP model into a deployed and monitored production service. Beyond improving model accuracy, the project emphasized reproducible evaluation, error analysis, deployment, observability, and technical documentation. These stages collectively transformed a simple sentiment classifier into a maintainable AI application that follows many of the practices used in real-world machine learning engineering.
